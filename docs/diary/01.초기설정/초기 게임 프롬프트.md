플레이 캐릭터가 Chrome 공룡게임처럼 계속 오른쪽방향으로 달리며 장애물을 피하는 게임이야.

# 개발 스택

- 플레이 캐릭터

    - 상단 장애물 소, 중, 대

- 게임 오버

# 🎮 무한 횡스크롤 러너 게임 개발 명세서
1. 게임 개요
장르: Endless Side-scrolling Runner
컨셉: Chrome 공룡 게임과 유사한 무한 횡스크롤 게임. 플레이어 캐릭터가 오른쪽으로 계속 달리며 상단/하단 장애물을 회피하는 게임
핵심 목표: 최대한 오래 생존하며 높은 점수 획득

2. 기술 스택

언어: 순수 JavaScript (ES6+)
렌더링: Canvas API (2D Context)
프레임워크: 없음 (Vanilla JS)
목표 프레임레이트: 60 FPS


3. 게임 메커니즘
3.1 캐릭터 시스템
기본 속성

캐릭터 크기: 50x50px
초기 위치: 화면 왼쪽에서 20% 지점, 지면 위
기본 이동 속도: 5px/frame (좌우 이동 없음, 자동 전진)

물리 시스템

중력: 0.6px/frame²
점프 메커니즘:

짧은 터치 (스페이스바 0.1초 미만): 낮은 점프 (초기 속도 -10px/frame)
중간 터치 (0.1~0.3초): 중간 점프 (초기 속도 -13px/frame)
긴 터치 (0.3초 이상): 높은 점프 (초기 속도 -16px/frame)
최대 점프 높이: 250px
공중에서 추가 점프 불가 (더블 점프 금지)



애니메이션

달리기: 4프레임 스프라이트, 0.1초마다 프레임 전환
점프: 별도 점프 프레임 (선택사항)
착지: 부드러운 착지 애니메이션 (선택사항)

3.2 장애물 시스템
종류 및 크기

하단 장애물 (지면 위치)

소: 30x30px
중: 50x50px
대: 70x70px


상단 장애물 (화면 상단에서 하강)

소: 30x30px (낮은 높이 비행)
중: 50x50px (중간 높이 비행)
대: 70x70px (높은 위치 비행)



생성 규칙

초기 생성 간격: 1800px ~ 2500px (랜덤)
최소 안전 간격: 800px (어떤 경우에도 최소 이 거리 유지)
최대 생성 간격: 3000px
상단/하단 장애물 비율: 60% 하단, 40% 상단
연속 생성 방지: 같은 타입(상단/하단)이 2회 이상 연속 생성되지 않도록 제어

난이도별 생성 패턴

초반 (0~300점): 하단 소/중 위주, 간격 넓음
중반 (300~800점): 모든 크기 등장, 상단 장애물 빈도 증가
후반 (800점 이상): 큰 장애물 증가, 간격 최소화, 복합 패턴

이동 속도

장애물은 게임 속도와 동일하게 왼쪽으로 이동
화면 왼쪽 끝을 벗어나면 제거

3.3 점수 시스템
점수 획득 방식

시간 기반: 0.1초마다 1점
장애물 회피: 장애물 1개를 완전히 통과할 때마다 10점 보너스
완벽한 착지: 연속 3회 장애물 회피 시 50점 콤보 보너스

점수 표시

실시간 점수: 화면 우측 상단
최고 점수: 화면 좌측 상단 (로컬 스토리지에 저장)
게임 오버 시: 현재 점수, 최고 점수, 통과한 장애물 수 표시

3.4 난이도 증가 시스템
단계별 난이도
점수 구간게임 속도장애물 간격큰 장애물 확률0~2005px/f2000~2500px10%200~5006px/f1600~2200px25%500~10007px/f1400~2000px40%1000+8px/f1200~1800px55%
속도 증가 곡선

100점마다 이동 속도 +0.2px/frame
최대 속도: 10px/frame (캡 적용)

장애물 밀도 증가

200점마다 최소 생성 간격 -50px
최소 간격 하한선: 800px


4. 조작 및 입력
4.1 키보드 입력

스페이스바 (Space)

누르기: 점프 차징 시작
떼기: 차징된 힘으로 점프
게임 오버 상태에서: 재시작


ESC

게임 중: 일시정지 및 설정 메뉴 열기
메뉴에서: 메뉴 닫기


Enter (선택사항)

게임 시작 화면에서 게임 시작

7. 게임 상태 관리
7.1 게임 상태 (State)
javascriptconst GameState = {
  MENU: 'menu',           // 시작 화면
  PLAYING: 'playing',     // 게임 진행 중
  PAUSED: 'paused',       // 일시정지
  GAME_OVER: 'gameOver'   // 게임 오버
}
7.2 상태 전환 흐름
MENU → (스페이스바) → PLAYING
PLAYING → (ESC) → PAUSED
PAUSED → (ESC/계속하기) → PLAYING
PLAYING → (충돌) → GAME_OVER
GAME_OVER → (스페이스바/다시하기) → PLAYING

8. 충돌 감지
8.1 충돌 감지 방식
사각형 충돌 (Bounding Box)

각 객체의 x, y, width, height를 기준으로 AABB 충돌 검사
약간의 여유 공간(padding) 적용: 실제 크기의 80% 판정 (플레이어에게 유리하게)

충돌 검사 타이밍

매 프레임마다 캐릭터와 모든 활성 장애물 간 충돌 검사
충돌 시 즉시 게임 오버 상태로 전환

8.2 충돌 판정 최적화

화면 밖 장애물은 검사 제외
캐릭터 뒤로 지나간 장애물은 검사 제외


9. 성능 및 최적화
9.1 최적화 전략

오브젝트 풀링: 장애물 객체 재사용
화면 밖 객체 제거: 왼쪽 화면을 벗어난 장애물 즉시 제거
이미지 사전 로딩: 게임 시작 전 모든 이미지 미리 로드
requestAnimationFrame 사용: 부드러운 60fps 유지

9.2 Canvas 렌더링 최적화

매 프레임 전체 캔버스를 지우지 말고, 변경된 영역만 다시 그리기 (Dirty Rectangle)
레이어 분리: 배경, 게임 오브젝트, UI를 별도 캔버스로 분리 (선택사항)
