# 맵 배경화면 스크롤링 시스템 구현

## 개요
점수에 따라 자동으로 전환되는 배경 이미지 시스템 구현
- **초원 맵**: 3개 이미지 (0~1000점)
- **용암 맵**: 2개 이미지 (1000~3000점)
- **빙하 맵**: 3개 이미지 (3000점 이상)

각 맵별로 부드러운 무한 스크롤링 및 페이드 전환 효과 적용

## 구현 요청사항

### 1. 배경 이미지 설정

#### 초원 맵 (0~1000점)
- **파일 경로**: `src/assets/images/background/glassland/`
- **이미지 파일**:
  - `map_01.png` (0~350점)
  - `map_02.png` (351~700점)
  - `map_03.png` (701~1000점)
- **스크롤 속도**: 게임 속도의 30% (0.3배) - 패럴랙스 효과

#### 용암 맵 (1000~3000점)
- **파일 경로**: `src/assets/images/background/lava/`
- **이미지 파일**:
  - `map_01.png` (1000~2000점)
  - `map_02.png` (2001~3000점)
- **스크롤 속도**: 게임 속도의 30% (0.3배) - 패럴랙스 효과

#### 빙하 맵 (3000점~)
- **파일 경로**: `src/assets/images/background/ice/`
- **이미지 파일**:
  - `map_01.png` (3001~4000점)
  - `map_02.png` (4001~5000점)
  - `map_03.png` (5001점~)
- **스크롤 속도**: 게임 속도의 5% (0.05배) - 매우 느린 스크롤 (한 번만 지나가도록)

### 2. 배경 스크롤 동작 방식
```
게임 화면: @@@@
배경 이미지: ===================

1) @@@@
   ===================

2)   @@@@
   ===================

3)     @@@@
   ===================
```

- 카메라가 오른쪽으로 이동하면 배경은 왼쪽으로 스크롤
- 패럴랙스 효과: 배경은 게임 속도의 30% 속도로 이동
- 무한 반복: 이미지가 화면 밖으로 나가면 끊김 없이 반복

## 해결한 주요 문제들

### 문제 1: 특정 구간에서 끊김 현상
**원인**: 음수 모듈로 연산 시 예상치 못한 값 발생

**해결**: 양수 정규화 공식 적용
```javascript
// 기존 (문제 있음)
const scrollX = (-this.backgroundX * 0.3) % scaledWidth;

// 수정됨 (해결)
const normalizedScroll = ((scrollDistance % scaledWidth) + scaledWidth) % scaledWidth;
```

### 문제 2: 점수 200 부근에서 끊김
**원인**: backgroundX를 -1280에서 0으로 리셋하면서 갑자기 점프

**해결**: 리셋 로직 제거, 렌더링에서 모듈로 연산으로 처리
```javascript
// 기존 (문제 있음)
if (this.backgroundX <= -1280) {
    this.backgroundX = 0;  // 갑자기 점프
}

// 수정됨 (해결)
this.backgroundX -= gameSpeed * 0.3;
// 리셋 없이 계속 증가
```

### 문제 3: map_02, map_03이 중간부터 시작
**원인**: 맵 전환 시 backgroundX 값이 큰 음수로 남아있음

**해결**: 맵 전환 시 backgroundX 리셋
```javascript
startBackgroundTransition(newMap) {
    this.backgroundX = 0;  // 새 맵은 처음부터 시작
    this.isBackgroundTransitioning = true;
    this.backgroundTransitionAlpha = 0;
}
```

### 문제 4: 빙하 맵 배경이 반복해서 나타남
**원인**: 초원/용암 맵과 동일한 스크롤 속도 (0.3배) 사용

**해결**: 빙하 맵만 스크롤 속도를 0.05배로 변경
```javascript
// 초원/용암 맵
const scrollDistance = this.backgroundX * 0.3;  // 빠른 스크롤

// 빙하 맵
const scrollDistance = this.backgroundX * 0.05;  // 느린 스크롤 (한 번만)
```

### 무한 스크롤링 알고리즘
```javascript
// 초원/용암 맵: 빠른 스크롤 (반복 스크롤링)
const scrollDistance = this.backgroundX * 0.3;  // 패럴랙스 0.3배
const normalizedScroll = ((scrollDistance % scaledWidth) + scaledWidth) % scaledWidth;

const x1 = normalizedScroll;
const x2 = normalizedScroll - scaledWidth;

// 2-3개 이미지를 그려서 끊김 없는 무한 스크롤링 구현
this.ctx.drawImage(img, x1, 0, scaledWidth, 720);
this.ctx.drawImage(img, x2, 0, scaledWidth, 720);
if (x1 > 0 || x2 + scaledWidth < 1280) {
    this.ctx.drawImage(img, x2 - scaledWidth, 0, scaledWidth, 720);
}
```

```javascript
// 빙하 맵: 느린 스크롤 (한 번만 지나가도록)
const scrollDistance = this.backgroundX * 0.05;  // 패럴랙스 0.05배
const normalizedScroll = ((scrollDistance % scaledWidth) + scaledWidth) % scaledWidth;

// 동일한 렌더링 로직이지만 느린 속도로 인해 해당 점수 구간 동안 한 번만 표시
```

### 페이드 전환 효과
```javascript
if (isBackgroundTransitioning && previousBackgroundMap) {
    // 이전 배경 (100% 불투명)
    renderBackgroundByName(previousBackgroundMap);
    
    // 새 배경 (점점 불투명하게)
    ctx.globalAlpha = backgroundTransitionAlpha;  // 0 → 1
    renderBackgroundByName(currentBackgroundMap);
    ctx.globalAlpha = 1.0;
}
```

## 기술적 참고사항

### GIF 파일 사용 가능 여부
**Canvas의 GIF 제약**:
- Image 객체로 GIF 로드 가능
- drawImage()는 첫 프레임만 렌더링
- 애니메이션 재생 불가

**대안**:
1. **스프라이트 시트** (권장): 모든 프레임을 하나의 PNG에, 게임 표준 방식
2. **PNG 시퀀스**: 여러 PNG를 순서대로 전환, 품질 좋음
3. **Video (WebM/MP4)**: video 요소를 Canvas에 그리기, 압축률 좋음
4. **코드 애니메이션** (현재 방식): 정적 PNG + JavaScript 애니메이션, 가볍고 성능 좋음

### 스크롤 속도 차이의 이유
- **초원/용암 맵 (0.3배)**: 반복적으로 지나가는 배경을 자연스럽게 표현
- **빙하 맵 (0.05배)**: 각 점수 구간마다 배경이 한 번만 지나가도록 연출
- 게임 진행에 따라 다른 시각적 경험 제공

### 이미지 스케일링 방식
- 캔버스 높이 720px에 맞춰 이미지 세로 크기 고정
- 가로 비율 유지하여 원본 이미지 왜곡 방지
- 이미지 원본 크기에 상관없이 일관된 표시
